# Shopee 插件功能重建

這個工作區保存一份使用者提供的舊版插件作靜態分析，並建立以 Shopee Open Platform 為資料來源的新實作。舊版原碼放在 `legacy-extension/`，由 `.gitignore` 排除，避免在清理原有授權服務與憑證處理前誤公開。

目前完成：

- [功能盤點與遷移矩陣](docs/feature-inventory.md)
- [對接架構與驗收標準](docs/integration-architecture.md)
- `open-platform/`：後端使用的 Shopee 請求簽名、GET/POST、店鋪授權 URL、交換與刷新 Token、加密保存及按店鋪自動刷新；已按官方文件加入商品列表、廣告活動列表／設定／每日與每小時績效、手動商品廣告和店鋪 GMV Max 適配器；另已移植利潤計算和預算水位線判定核心並編寫單元測試
- `extension/`：全新 Manifest V3 插件源碼；彈窗有控制台入口，控制台列出舊插件 23 項功能及逐項狀態；只連本機後端，不讀蝦皮登入 Cookie，也不保存 Partner Key
- `dist/extension/`：執行建置後產生的可載入插件目錄（不提交版本庫）

0.3.0 開發版的彈窗會即時核對本機配對碼與沙盒店鋪授權；控制台會讀取沙盒在架商品及廣告活動數量，活動列表支援類型、起始位置與每頁件數查詢。「打開賣家中心」會進入臺灣沙盒站。

0.4.0 開發版新增「指定商品開廣告」中的沙盒單件手動選品試建：先預覽商品 ID、預算、日期及可選 ROAS，再確認送出。後端只接受與目前沙盒 Shop ID 一致、且含明確確認標記的請求。2026-11-03 已用商品 `846071597` 成功建立沙盒活動 `151139`（每日預算 TWD 85），並讀回活動設定與每日／每小時績效；原版批量廣告功能仍未完成。

0.5.0 開發版讓活動列表顯示名稱、狀態、預算、商品 ID 與目標 ROAS；績效表加入 CPC。另加入沙盒單件手動選品廣告修改工具，先讀取並預覽活動設定，確認後才送出，後端會再次核對目前設定。活動 `151139` 的預算修改已實測 85 → 90 → 85，兩次均讀回確認；ROAS 修改和暫停／恢復尚未實測。

0.5.1 開發版已實測活動 `151139` 的暫停及恢復，最後狀態仍為 `ongoing`。蝦皮沙盒拒絕對 `auto` 競價活動直接修改目標 ROAS；插件和後端源碼已加入預先阻止與說明。讀回設定偶發失敗時，插件會清楚顯示「請求已送出、讀回未確認」，避免誤以為可直接重試。

0.6.0 開發版增加「批量篩選廣告」的只讀工具：每頁最多 100 個活動，按日期、活動狀態、商品 ID、點擊、CPC、花費和 ROAS 篩選，並將目前結果匯出 CSV。資料來自活動設定和每日績效 API；跨頁自動掃描及篩選後刪除尚未接入。

0.7.0 開發版增加「廣告健康檢查」的只讀工具：檢查單頁活動設定、關聯商品狀態與指定日期的曝光／點擊。商品清單未覆蓋的 ID 顯示「未確認」，不當作違規；目前沒有可用的官方違規原因欄位，因此不宣稱能判定蝦皮違規。

0.8.0 開發版新增最多 10 個指定活動的沙盒批量預算修改工具。執行前讀取並預覽每個活動設定；送出時逐個修改、逐個讀回，遇到 API 失敗或結果不明就停止。最近一次執行狀態保存在插件本地儲存空間，供重新核對；此批量介面尚未在 Chrome 中實測。

0.9.0 開發版在「全店開啟廣告」加入在架商品投放預覽：比對商品與已掃描活動的關聯商品 ID；若活動未掃完，只顯示「未確認」，不宣稱可投放。單件試建工具移除自動競價模式下無效的目標 ROAS 輸入。此預覽不檢查庫存或建立資格，也不會批量建立活動。

0.9.1 修正控制台任務面板：批量預算任務的活動數、已處理數、已確認數和待核對數會從本機執行記錄更新；利潤計算器的輸入值也會保存在插件本機，彈窗與控制台共用。

0.9.2 防止計算器載入舊設定時覆蓋正在編輯的輸入；保存失敗也會保留已計算的結果。任務面板用「已開始」標示已進入執行流程的活動。

0.9.3 對照舊版 6.9.9 的各頁籤，補齊控制台 23 項功能的參數預覽，包括原先僅有簡介的廣告、預算、商品、物流和行銷表單。未接入的操作按鈕維持停用，已接入的沙盒工具保留在相應頁籤。畫面仍未達到逐像素一致，實際 API 能力也未與舊版完全相同；差異及下一步見[UI／API 對照驗收](docs/ui-api-parity.md)。

0.9.4 廣告篩選與健康檢查改為逐頁讀取，最多 10 頁、1000 個活動；顯示掃描進度與剩餘資料位置。遇到重複活動 ID 或不完整分頁即停止；篩選尚未讀完活動清單時不提供 CSV 匯出。這仍不是原版的無上限全店掃描，其他條件及刪除流程尚未完成。

0.9.5 對照原版控制台，重排「全店開啟廣告」「批量開廣告群組」「CPC 監控自動重開」「批量刪除廣告」四個頁籤的欄位、分區、操作卡片和按鈕 ID。全店頁的「僅查詢商品」會呼叫已接入的只讀預覽；CPC 頁下方保留已接入的績效查詢。批量建立、監控、刪除仍未完成官方 API 對照，按鈕維持停用。詳見 [UI／API 對照驗收](docs/ui-api-parity.md)。

0.9.6 繼續對齊廣告控制台第 5–8 頁：「商品批量操作」「指定商品開廣告」「批量修改 ROI／預算」「加速推廣控制」。依原版保留操作類型聯動欄位、手動／自動區、ROI 與預算雙欄，以及加速推廣的自動／手動 ID 模式。已接通的商品查詢、沙盒單件建廣告與單件／指定活動預算工具仍在對應頁下方；原版批量操作的按鈕尚未接通。「批量刪除廣告」另新增只讀範圍預覽，按指定或排除商品 ID 掃描最多 1000 個活動，不會送出刪除。

0.9.7 對照原版重排「重開廣告」「批量篩選廣告」「廣告健康檢查」「修改標題」四頁的欄位與分區：重開頁分手動／系統 ROI，含指定／排除模式及延遲時間；篩選頁分數據條件及商品 ID 過濾，目標 ROI 和成本的區間欄位會依選項顯示；健康檢查頁保留狀態選擇和結果區；修改標題頁可只讀核對前 100 件在架商品中的指定 ID。原版重開、批量刪除、健康掃描、標題寫入與推薦關鍵詞按鈕尚未接線；下方仍提供已接通的只讀篩選匯出和健康資料檢查工具。這些只讀工具的篩選條件與原版尚未完全一致。

0.9.8 將預算水位線從單張參數預覽改為原版的多規則工作區：商品 ID、追加金額、預算上限、消耗水位、23:55 動作、次日恢復、不同時間段的 ROI、加預算時間窗均有對應欄位；新增／移除規則和依勾選顯示欄位可操作。每條規則可把數值門檻帶入下方樣本計算器。這只預覽數值門檻，不會執行時間窗、輪詢、日終還原或店鋪寫入。

0.9.9 對照原版重排「批量發貨天數」：現貨／預售切換、四種商品範圍、銷量頭部比例、排除 ID、滿額贈排除入口、物流聯動及兩項定時任務。已接入上架、下架或兩者合併的前 100 件商品只讀範圍預覽，並可排除輸入的商品 ID；未接入銷量排序、特賣／滿額贈排除及任何備貨天數寫入，因此非熱銷模式無法安全預覽，真正更新與排程按鈕保持停用。

0.9.11 對照原版重排「組合促銷」「折扣活動」「滿額贈」三頁：商品範圍切換、滿件數、減免額、每人限購、折數、贈品 ID、已有活動選擇區和原版操作 ID 均在對應頁。已接入前 100 件在架商品的只讀範圍或贈品 ID 核對；活動衝突、商品資格、備貨天數及行銷寫入 API 尚未驗證，建立與修改按鈕停用。

0.9.12 商品管理導航加入原版第三個「物流設定」入口，會打開新版物流頁；限時特賣頁改為原版彈窗的續期狀態及開／關結構。原版限時特賣另含賣家中心活動列表的刪除操作，仍須官方 API 對照；開／關和刪除尚未啟用。

0.9.13 預算水位線工作區新增「複製規則」，複製後清空商品 ID，方便套用相同參數到另一組商品。規則、ROI 時間點、加預算時間段及狀態篩選會自動保存到目前 Chrome 的本機儲存空間，重開頁面後還原。這只是表單草稿，不會啟動輪詢或修改店鋪；草稿不會透過 GitHub 同步到其他電腦。

0.9.14 預算規則的「添加商品」會開啟在架商品選擇視窗，可逐頁讀取沙盒商品、按本頁 ID 搜尋、全選或反選，再將選中的 ID 回填目前規則；已在其他規則的 ID 不能重複選。原版選擇器還支援按廣告和 ROI 等條件查詢，這些條件尚未接通，頁面已明確提示。

0.9.15 預算商品選擇器會只讀掃描最多 1000 個廣告活動，取得進行中活動的商品 ID；預設只顯示已核對為進行中廣告的本頁商品。可切換全部在架商品，且只有活動掃描完整才可判定「未出現在進行中廣告」。廣告查詢失敗時退回全部在架商品。ROI 類型、日期、標題與績效排序仍須官方資料對照。

0.9.16 廣告篩選頁下方的沙盒只讀工具新增「任一／全部數據條件」選擇。點擊、CPC、ROAS 與花費的已填門檻參與組合；日期、狀態及商品 ID 仍限定查詢範圍。缺少 CPC 或 ROAS 時不會當成 0 命中。原版上方完整表單的查詢、刪除按鈕仍未接線。

0.9.17 原版篩選頁上方「查詢廣告」已接只讀沙盒掃描，支援日期預設、進行中／全部、指定與排除商品 ID、曝光、點擊、CPC、ROAS、目標 ROAS、花費及任一／全部條件。查詢結果可預覽；掃描完整時可下載活動表和匹配 ID。績效缺資料時標為未知，不會當成 0。原版加速推廣狀態尚無已核實欄位，選非「全部」會提示；批量刪除仍停用，活動績效不可冒充逐商品績效。

0.9.18 原版廣告健康檢查頁的上方「開始掃描」已接只讀沙盒資料檢查，能選進行中或全部狀態；下方工具共用同一掃描與分類。結果區分「需核對設定」「資料未確認」「已核對欄位」，缺資料不算零曝光，零曝光也不算蝦皮違規。最多掃描 1000 活動，商品狀態只讀前 100 件；官方違規原因及商品標題仍未接通。

0.9.19 批量修改預算頁上方的指定／排除商品 ID 按鈕會只讀掃描手動廣告並核對關聯；清單未掃完、關聯缺失、指定 ID 找不到或符合活動超過 10 個時停止。符合條件的活動 ID 帶入下方安全預覽，仍需另按「確認批量修改」才會寫入沙盒；上方條件變動會清除舊預覽。批量 ROI 和加速推廣仍未接通。

0.9.20 批量修改 ROI 頁上方的指定／排除商品 ID 按鈕也接入完整掃描與下方安全預覽。只允許正數目標 ROAS 且廣告為 manual 競價；auto 競價、ROI=0 系統模式切換、加速推廣會明確阻止。最多 10 個活動，逐筆修改及讀回、失敗即停，並保留本機記錄。現有沙盒廣告是 auto 競價，尚無可執行正數 ROAS 的 manual 活動，因此批量 ROAS 介面與寫入仍未實測。

目前插件能在本地計算利潤和預覽預算規則，並在後端配置及沙盒授權完成後查詢商品、廣告活動及績效；單件建立、預算修改、暫停與恢復已接入並實測。控制台中「部分完成」和「待對接 API」不表示原插件的批量或定時操作已完成。2026-11-03 已用 CF 測試 App 授權沙盒 Shop ID `228006723`，商品列表回傳 1 件（商品 ID `846071597`），並建立單件沙盒廣告 `151139`；廣告活動列表、設定、績效、單件預算修改和暫停／恢復均已實測成功。批量預算／ROAS 介面及其他寫入動作尚未實測。App 處於測試階段；沒有在插件、源碼或文件中寫入 Partner Key、Access Token、Refresh Token。

執行測試：

```powershell
cd open-platform
node --test
node scripts/build-extension.js
```

本機後端需要環境變數 `SHOPEE_PARTNER_ID`、`SHOPEE_PARTNER_KEY`、`SHOPEE_SHOP_ID`、`SHOPEE_REDIRECT_URL`、`SHOPEE_VAULT_KEY_BASE64`，然後執行 `node bin/server.js`。它只綁定 `127.0.0.1:8787`，啟動時會產生插件配對碼。不要把 Partner Key 或 Token 寫進插件或提交到版本庫。詳細步驟見[本機沙盒使用說明](docs/local-sandbox.md)。

## 在另一台電腦接續

在新電腦安裝 Git、Node.js 和 Chrome，然後下載這個倉庫：

```powershell
git clone https://github.com/chgptuser003-GH/jiejiejie.git
cd jiejiejie\open-platform
node --test
node scripts/build-extension.js
```

在 Chrome 的擴充功能管理頁開啟開發人員模式，選擇倉庫中的 `dist/extension/` 作為未封裝擴充功能。新電腦再執行 `scripts/start-sandbox.ps1`，在本機視窗輸入 CF 測試 Partner Key，將視窗顯示的配對碼填入插件，並重新授權沙盒店鋪。舊電腦的 Token Vault 受 Windows 使用者加密保護，**不會隨 GitHub 倉庫轉移**；這是正常情況。不要把 Partner Key、Token 或配對碼提交到 Git。

CF App 已通過商品列表、廣告活動列表／設定／績效的沙盒讀取，以及單件手動選品廣告建立、預算修改和暫停／恢復。`auto` 競價活動的目標 ROAS 修改遭沙盒拒絕；刪除、批量和其他 Ads 端點尚未驗證。後續逐項驗證商品、物流、行銷與廣告寫入功能，再建立批量任務與排程。
